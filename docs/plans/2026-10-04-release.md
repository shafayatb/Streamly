# 1.0 Release Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `develop` into the verified 1.0 submission: the four agreed download fixes, a
minified `benchmark` build that ships as the APK, a full end-to-end pass on both devices, and a
README with screenshots, the demo, and install and build instructions.

**Architecture:** The fixes stay inside the existing layers. `DownloadRepository.remove` becomes a
`suspend` call that reports failures, like `download`. `AccountDownloadRepository` prunes stale
owner records once per launch. The ViewModels show a snackbar when a removal fails and forget a
removal whose download disappears. The `benchmark` build type is a release copy with R8, debug
signing, and no debugging. The media and docs are produced from that build.

**Tech Stack:** Kotlin Multiplatform (Android target), Compose Multiplatform, Coroutines and Flow,
Koin, Media3 1.11, DataStore, AGP 9.1, R8, kotlin.test with Turbine, `adb`, `ffmpeg`.

**Spec:** The design agreed in the October 3 brainstorm, recorded in the "Agreed design" section
below, plus `FRESH_PROMPT.md` ("Submission deliverables" and "The October 4 release gate").

## Agreed design (user, October 3)

- **Fixes, bundle 1 only, each test-first:**
  - `formatBytes` picks the unit after rounding: 999,500 B reads "1.0 MB", not "1000 KB"; 9.95 MB
    reads "10 MB"; 999.5 MB reads "1.0 GB".
  - The remove dialog: `DownloadsViewModel` clears `pendingRemovalId` once its item disappears, so
    the dialog never comes back; the Player clears its dialog flag once the download is no longer
    completed, and only opens it for a completed download.
  - A failed removal tells the user: `DownloadRepository.remove` becomes
    `suspend fun remove(videoId: String): EmptyResult<DataError.Local>`, run in the repository's
    app-wide scope; Downloads and the Player show "Couldn’t remove the download. Please try
    again." `MediaDownloads.remove` always succeeds.
  - Prune owner records whose download no longer exists, once per launch, after the device
    downloads and the owners are both read, and only if no download has started in this run (a new
    download's owner is recorded before the device lists it).
- **Every other deferred minor** goes to the README's known gaps.
- **Benchmark build:** `initWith(release)`, debug-signed, not debuggable, R8 minify and resource
  shrinking, keep rules only for what R8 actually breaks. `release` is unchanged. It is the
  shipped APK, committed at `apk/streamly-1.0-benchmark.apk`.
- **Verification split:** the emulator runs the full pass on the **debug** build (log evidence),
  plus tablet, landscape, dark mode, and offline errors; the A04 runs the full pass on the
  **benchmark** build from a clean install. `check` passes, and the device tests run on both
  devices.
- **Media:** plain screenshots from the benchmark build (phone views on the A04; tablet and
  landscape on the emulator) in `docs/media/screenshots/`. A silent, roughly 3-minute demo
  recorded on the A04 from the benchmark build, cut together with `ffmpeg`, at
  `docs/media/streamly-demo.mp4`, under 50 MB. The README shows a poster image
  (`docs/media/demo-poster.jpg`) linking to the MP4, then chapter timestamps.
- **Hosting:** the APK and the MP4 are committed and reach `main` with the `--no-ff` merge; the
  user shares their GitHub links. No Git LFS.

## Global Constraints

- Kotlin only; Coroutines and Flow; Compose for all UI; MVVM + MVI (one `UiState`, one sealed
  intent per screen); the domain layer has no Android imports; Koin; Media3 only.
- Compose resource strings use a typographic apostrophe (’), never `\'`.
- No commit or merge without the user's explicit approval. Conventional Commits, each ending with:
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_012TmSE8GezgT8pMHHsddWP9`.
- Do not push, tag, or open a PR unless the user asks. Never delete branches.
- Each committed binary is under 50 MB.
- Use `rtk proxy ./gradlew …` and `rtk proxy git …` for raw output.

## Review Focus

- **R8 strips something used by reflection or serialization** (watch-history JSON, Koin
  ViewModels, Compose resources, Media3's download service): every screen and every persisted
  store must work on the benchmark build. Pinned by Task 6's A04 pass, which restarts the app to
  read each store back.
- **Pruning removes a record that is still needed:** an unfinished download (queued, waiting for
  Wi-Fi) or one started right after launch must keep its owner. Pinned by Task 4's tests.
- **A removal that fails leaves the files and says so,** and a removal for one of two owners never
  deletes the other's files. Pinned by Task 3's tests.
- **The dialog never reappears for a video downloaded again** after it vanished. Pinned by Task
  2's tests.
- **Deliverable size limits:** the APK and MP4 must stay under 50 MB, or GitHub warns or rejects
  the push. Checked in Task 7.

/** Sizes in decimal units, as Android's storage settings show them: "4.2 MB", "66 MB", "1.2 GB". */
fun formatBytes(bytes: Long): String = when {
    bytes < 1_000 -> "$bytes B"
    // Each bound is where the rounded figure would reach the next unit, so "1000 KB" never shows.
    bytes < 999_500 -> "${roundedDiv(bytes, 1_000)} KB"
    bytes < 9_950_000 -> "${oneDecimal(bytes, 1_000_000)} MB"
    bytes < 999_500_000 -> "${roundedDiv(bytes, 1_000_000)} MB"
    else -> "${oneDecimal(bytes, 1_000_000_000)} GB"
}

```kotlin
    override suspend fun remove(videoId: String): EmptyResult<DataError.Local> {
        starts.remove(videoId)?.cancel()
        // In this object's scope, like a start: leaving the screen must not stop between dropping
        // the owner and deleting the files.
        return scope.async { removeOwned(videoId) }.await()
    }

    private suspend fun removeOwned(videoId: String): EmptyResult<DataError.Local> {
        // Signed out, nothing is owned, so there is nothing to remove.
        val account = account.first() ?: return Result.Success(Unit)
        return when (val result = ownership.removeOwner(videoId, account)) {
            is Result.Failure -> result
            is Result.Success -> if (result.data.isEmpty()) device.remove(videoId) else Result.Success(Unit)
        }
    }
```

        scope.launch {

                    if (hasStarted) return@launch
